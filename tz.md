# Техническое задание: VPN-маршрутизация по спискам IP

## 1. Общая информация

### 1.1 Цель проекта
Автоматическая маршрутизация трафика к определённым ресурсам (WhatsApp, Telegram и др.) через VPN-интерфейс на роутере Keenetic.

### 1.2 Оборудование
- **Роутер:** Keenetic KN-1012 (Start)
- **CPU:** MediaTek MT7628N, 580 MHz
- **RAM:** 64 MB
- **Прошивка:** с поддержкой OPKG/Entware

### 1.3 Доступ
- **SSH:** `ssh -p 222 root@192.168.1.1`
- **Пароль:** `<ROUTER_PASSWORD>`

---

## 2. Функциональные требования

### 2.1 Источник данных
- **URL:** `https://iplist.opencck.org/?format=bat&data=cidr4&site=whatsapp.com`
- URL задаётся переменной в конфигурации скрипта
- Поддерживаются расширенные параметры URL, включая `exclude[cidr4]=...` для исключения подсетей
- Формат ответа (Windows BAT):
```
route add 1.0.0.0 mask 255.128.0.0 0.0.0.0
route add 101.48.0.0 mask 255.248.0.0 0.0.0.0
route add 102.0.0.0 mask 255.0.0.0 0.0.0.0
```

**Пример URL с исключением подсети:**
```
https://iplist.opencck.org/?format=bat&data=cidr4&site=whatsapp.com&exclude[cidr4]=213.59.192.0/18
```

### 2.2 VPN-интерфейс
- **Имя интерфейса:** `<VPN_INTERFACE>` (WireGuard)
- Имя задаётся переменной в конфигурации скрипта

### 2.3 Количество маршрутов
- Ожидаемое количество: 500 — 5000+ записей
- Требуется оптимизация для больших списков

### 2.4 Расписание
- Автоматическое обновление: **ежедневно в 04:00**
- Автозапуск при старте роутера

## 3. Техническое решение

### 3.1 Технология: ipset + policy routing
Выбрано для оптимальной производительности на слабом железе:

| Компонент | Назначение |
|-----------|------------|
| **ipset** | Хранение списка подсетей (hash:net, O(1) lookup) |
| **iptables** | Маркировка пакетов к адресам из ipset |
| **ip rule** | Policy routing по метке |
| **ip route** | Отдельная таблица маршрутизации для VPN |

### 3.2 Язык реализации
**Bash** — минимальное потребление ресурсов, всё необходимое есть в Entware.

### 3.3 Структура скрипта (функции)
```
vpn-routes.sh
├── log()              — логирование с timestamp
├── check_deps()       — проверка зависимостей
├── get_interface()    — получение имени сетевого интерфейса
├── fetch_routes()     — скачивание списка с URL
├── parse_routes()     — конвертация Windows→Linux формат
├── clear_ipset()      — очистка старого ipset
├── apply_ipset()      — добавление записей в ipset
├── setup_routing()    — настройка iptables + ip rule
├── cleanup_routing()  — удаление правил маршрутизации
├── main()             — основная логика
```

### 3.4 Необходимые пакеты (Entware)
```bash
opkg install ipset iptables curl ca-certificates
```

## 11. Известные проблемы и решения

### 11.1 URL со спецсимволами `[` и `]`

**Проблема:** URL с параметрами вида `exclude[cidr4]=...` не скачиваются через curl.

**Причина:** curl интерпретирует квадратные скобки `[]` как glob-паттерн.

**Решение:** Использовать флаг `-g` (globoff) в команде curl:
```bash
curl -g -s --connect-timeout 30 -o "$temp_file" "$ROUTES_URL"
```

### 11.2 Ошибка 127 при перезапуске через API

**Проблема:** При вызове restart через веб-интерфейс возникает "Exit code: 127".

**Причина:** Переменная PATH не установлена при вызове скрипта через CGI.

**Решение:** Добавить PATH в начало vpn-routes.sh:
```bash
#!/bin/sh
PATH=/opt/bin:/opt/sbin:/usr/bin:/usr/sbin:/bin:/sbin
export PATH
```

### 11.3 Повреждение URL с символом `&` при сохранении

**Проблема:** URL с несколькими параметрами (`&site=...&site=...`) сохраняется некорректно.

**Причина:** Символ `&` в sed-замене означает "вставить найденный текст".

**Решение:** Экранировать спецсимволы sed в config.cgi:
```bash
new_url_escaped=$(printf '%s' "$new_url" | sed -e 's/\\/\\\\/g' -e 's/&/\\&/g' -e 's/|/\\|/g')
sed -i "s|^ROUTES_URL=.*|ROUTES_URL=\"$new_url_escaped\"|" "$CONFIG_FILE"
```
