# Техническое задание: VPN Routes Dashboard

## 1. Общая информация

### 1.1 Цель
Веб-интерфейс для управления скриптом VPN Routes на роутере Keenetic.

### 1.2 Доступ
- **URL:** `http://192.168.1.1:8080`
- **Авторизация:** не требуется (доверенная домашняя сеть)

### 1.3 Ограничения
- RAM роутера: 64 MB
- Минимальное потребление ресурсов
- Вся "тяжёлая" работа (рендеринг UI) — в браузере

## 4. API Endpoints

### 4.1 GET /api/status
Возвращает текущий статус системы.

**Response:**
```json
{
  "status": "active",
  "interface": "nwg1",
  "interface_up": true,
  "ipset_count": 497,
  "routes_count": 497,
  "last_update": "2025-12-16 21:17:33",
  "iptables_prerouting": true,
  "iptables_output": true,
  "ip_rule": true
}
```

### 4.2 GET /api/config
Возвращает текущую конфигурацию.

**Response:**
```json
{
  "routes_url": "https://iplist.opencck.org/?format=bat&data=cidr4&site=whatsapp.com",
  "vpn_interface": "nwg1",
  "ipset_name": "vpn_routes",
  "fwmark": "0x1",
  "route_table": "100"
}
```

### 4.3 POST /api/config
Сохраняет конфигурацию.

**Request:**
```json
{
  "routes_url": "https://...",
  "vpn_interface": "nwg1"
}
```

**Response:**
```json
{
  "success": true
}
```

### 4.4 POST /api/restart
Перезапускает скрипт (restart).

**Response:**
```json
{
  "success": true,
  "output": "[2025-12-16 21:17:25] [INFO] === Начало обновления..."
}
```

### 4.5 POST /api/stop
Останавливает скрипт (stop).

**Response:**
```json
{
  "success": true
}
```

### 4.6 GET /api/routes
Возвращает список маршрутов с пагинацией.

**Query params:**
- `page` — номер страницы (default: 1)
- `per_page` — записей на страницу (default: 50)
- `search` — фильтр по подсети (optional)

**Response:**
```json
{
  "total": 497,
  "page": 1,
  "per_page": 50,
  "pages": 10,
  "routes": [
    "1.0.0.0/8",
    "101.48.0.0/13",
    "102.0.0.0/8"
  ]
}
```

### 4.7 GET /api/logs
Возвращает записи лога с фильтрацией.

**Query params:**
- `date` — дата в формате YYYY-MM-DD (default: сегодня)
- `level` — фильтр по уровню: info, error, debug, all (default: all)
- `search` — поиск по тексту (optional)
- `page` — номер страницы (default: 1)
- `per_page` — записей на страницу (default: 100)

**Response:**
```json
{
  "date": "2025-12-16",
  "total": 156,
  "page": 1,
  "per_page": 100,
  "pages": 2,
  "error_count": 3,
  "lines": [
    {"time": "21:17:25", "level": "INFO", "message": "=== Начало обновления маршрутов ==="},
    {"time": "21:17:25", "level": "INFO", "message": "Проверка зависимостей..."},
    {"time": "21:17:30", "level": "ERROR", "message": "Ошибка загрузки"}
  ]
}
```

### 4.8 GET /api/logs/dates
Возвращает список доступных дат логов.

**Response:**
```json
{
  "dates": [
    {"date": "2025-12-16", "size": 15234, "error_count": 3},
    {"date": "2025-12-15", "size": 12456, "error_count": 0},
    {"date": "2025-12-14", "size": 18923, "error_count": 1}
  ],
  "retention_days": 7
}
```

### 4.9 GET /api/interfaces
Возвращает список VPN интерфейсов.

**Response:**
```json
{
  "interfaces": [
    {"name": "nwg0", "ip": "10.13.1.136", "up": false},
    {"name": "nwg1", "ip": "10.8.0.12", "up": true}
  ]
}
```

### 4.10 POST /api/routes-clear
Очищает ipset и удаляет кэш маршрутов.

**Response:**
```json
{
  "success": true,
  "ipset_cleared": 1,
  "cache_deleted": 1
}
```

### 4.11 POST /api/logs-delete
Удаляет логи за указанную дату или все логи.

**Request (удалить за дату):**
```json
{
  "action": "delete_date",
  "date": "2025-12-16"
}
```

**Request (удалить все):**
```json
{
  "action": "delete_all"
}
```

**Response:**
```json
{
  "success": true,
  "message": "Deleted log for 2025-12-16"
}
```

## 10. Система логирования

### 10.1 Архитектура

```
┌─────────────────────────────────────────────────────────────┐
│                    vpn-routes.sh                            │
│                         │                                   │
│                    log() function                           │
│                         │                                   │
│                         ▼                                   │
│    /opt/var/log/vpn-routes/vpn-routes.YYYY-MM-DD.log       │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼ cron.daily
┌─────────────────────────────────────────────────────────────┐
│            vpn-routes-logrotate                             │
│  - Удаляет логи старше 7 дней                              │
│  - Обновляет симлинк vpn-routes.log → текущий день         │
└─────────────────────────────────────────────────────────────┘
```

### 10.2 Формат записи лога

```
[YYYY-MM-DD HH:MM:SS] [LEVEL] Message text
```

**Пример:**
```
[2025-12-16 21:17:25] [INFO] === Начало обновления маршрутов ===
[2025-12-16 21:17:26] [INFO] Загрузка списка маршрутов...
[2025-12-16 21:17:30] [ERROR] Ошибка загрузки: Connection timeout
```

### 10.3 Уровни логирования

| Уровень | Использование |
|---------|---------------|
| INFO | Обычные операции (запуск, остановка, обновление) |
| ERROR | Ошибки (сеть, файлы, команды) |
| DEBUG | Отладочная информация (опционально) |
| WARN | Предупреждения (некритичные проблемы) |

### 10.4 Ротация логов

**Файл:** `/opt/etc/cron.daily/vpn-routes-logrotate`

```bash
#!/bin/sh
# Удаление логов старше 7 дней
LOG_DIR="/opt/var/log/vpn-routes"
RETENTION_DAYS=7

find "$LOG_DIR" -name "vpn-routes.*.log" -mtime +$RETENTION_DAYS -delete

# Обновление симлинка на текущий день
TODAY=$(date '+%Y-%m-%d')
ln -sf "$LOG_DIR/vpn-routes.$TODAY.log" "$LOG_DIR/vpn-routes.log"
```

### 10.5 Изменения в vpn-routes.sh

Функция `log()` должна:
1. Записывать в файл с датой в имени: `vpn-routes.YYYY-MM-DD.log`
2. Создавать файл если не существует
3. Выводить в stderr для совместимости с функциями

```bash
log() {
    local level="$1"
    shift
    local message="$*"
    local timestamp=$(date '+%Y-%m-%d %H:%M:%S')
    local log_date=$(date '+%Y-%m-%d')
    local log_file="$LOG_DIR/vpn-routes.$log_date.log"
    local log_line="[$timestamp] [$level] $message"

    # В stderr (для совместимости с функциями)
    echo "$log_line" >&2

    # В файл
    mkdir -p "$LOG_DIR"
    echo "$log_line" >> "$log_file"
}
```

### 10.6 Конфигурация логирования

В `config.sh` добавить:

```bash
# Логирование
LOG_DIR="/opt/var/log/vpn-routes"
LOG_RETENTION_DAYS=7
LOG_LEVEL="INFO"  # INFO, DEBUG, ERROR
```

### 10.7 Парсинг логов в API

CGI скрипт `logs.cgi` парсит формат:
```
[YYYY-MM-DD HH:MM:SS] [LEVEL] Message
```

И возвращает структурированный JSON:
```json
{
  "time": "21:17:25",
  "level": "INFO",
  "message": "=== Начало обновления ==="
}
```

**Регулярное выражение для парсинга:**
```
^\[([0-9-]+) ([0-9:]+)\] \[([A-Z]+)\] (.*)$
```

## 11. Известные проблемы и решения

### 11.1 Ошибка 127 при перезапуске

**Симптом:** При нажатии "Перезапустить" появляется "Exit code: 127".

**Причина:** CGI-окружение не наследует PATH от системы.

**Решение:** Все CGI-скрипты должны явно устанавливать PATH:
```bash
#!/bin/sh
PATH=/opt/bin:/opt/sbin:/usr/bin:/usr/sbin:/bin:/sbin
```

### 11.2 URL с `&` сохраняется некорректно

**Симптом:** URL вида `?format=bat&data=cidr4` превращается в мусор после сохранения.

**Причина:** Символ `&` в sed означает "вставить найденный текст".

**Решение в config.cgi:**
```bash
new_url_escaped=$(printf '%s' "$new_url" | sed -e 's/\\/\\\\/g' -e 's/&/\\&/g' -e 's/|/\\|/g')
```

### 11.3 URL с `[]` не загружается

**Симптом:** URL вида `&exclude[cidr4]=...` вызывает "Ошибка загрузки маршрутов".

**Причина:** curl интерпретирует `[]` как glob-паттерн.

**Решение в vpn-routes.sh:**
```bash
curl -g -s --connect-timeout "$CURL_TIMEOUT" -o "$temp_file" "$ROUTES_URL"
```

Флаг `-g` (globoff) отключает glob-интерпретацию в URL.

### 11.4 SSH подключение к роутеру

**Команда:** `ssh -p 222 root@192.168.1.1`
